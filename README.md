# クラウド送信（LINEストックのフォーム営業）

ダッシュボードで「確認中」の会社に、問い合わせフォームから営業文を送るプログラムです。画面を出さないChromium（Playwright）で動くので、PCの重さに左右されず、Codexのクラウド環境でも動かせます。

- 送信データとステータスの置き場所：ダッシュボード（https://line-stock-product-plan.hitomi-k.workers.dev/#sales ）
- 入力の決まり：今夜Claudeが内蔵ブラウザで送った時と同じ（氏名・メール・電話・社名・件名・同意・止まる条件）

## ファイル

- `送信.mjs`：会社ID 1つ分を、入力→確認画面→送信→完了画面の判定まで行い、結果でステータスを変える
- `一括送信.mjs`：確認中の会社を1社ずつ順に `送信.mjs` で処理し、最後に件数と手で送る会社を出す
- `入力の判定.js`：フォームの各欄に何を入れるかを決める（/api/fill.js の判定を元にした）
- `AGENTS.md`：Codexのクラウドで動かす時の指示
- `記録/`：日付ごとの画面の写真と `送信ログ.jsonl`（Gitには入れない）

## 3つのモード

| モード | すること | ステータス |
|---|---|---|
| `dry`（既定） | 入力だけして止める。ボタンは押さない | 変えない |
| `confirm` | 「確認」ボタンだけ押し、確認画面で止める | 変えない |
| `send` | 送信まで行う | 送付完了／送付失敗／除外 に変える |

`confirm` は、ボタンの文字に「確認」があり「送信」がないボタンだけを押します。ただし、「確認」という名前で実際には送信まで進むフォームもあり得ます。`confirm` は、フォームのメモ（form_note）に「確認画面あり」と書いてある会社で使ってください。

## 1社の流れ

1. `/api/sales/<ID>/send-data` から、フォームURL・入力内容・本文を取る。ステータスが「確認中」でなければ何もしない。
2. フォームを開き、欄ごとに値を入れる。本文は一字一句入ったかを読み戻して確かめる。
3. 次のどれかに当たれば、送らずに止める。
   - 営業お断りの表記がある → 除外
   - 人の操作が要る認証（reCAPTCHAのチェック・画像選択、hCaptcha、通らないTurnstile、画像の文字・計算）→ 送付失敗（手で送る）
   - 自動で埋められない必須欄がある、選択欄に事実と違う初期値が入っている、本文が入らない → 送付失敗（理由とURLをメモに残す）
4. 確認ボタンがあれば押し、確認画面でもう一度、営業お断りの表記と認証を確かめる。
5. 送信の直前にダッシュボードのステータスを読み直し、まだ「確認中」の時だけ送信ボタンを1回押す。
6. 完了画面の文言（ありがとうございます、送信完了など）か、完了ページへのURLの変化で、送れたと判断する。
7. 送れたか分からない時は「送付失敗（送れたか不明。再送しない）」にし、もう一度は押さない。
8. 1社に10分以上かかったら打ち切り、送付失敗にする。

## 手元（Mac）で動かす

```bash
cd "成果物/クラウド送信"
npm install
npx playwright install chromium
node 送信.mjs LS-20261020-141 --mode=confirm
node 一括送信.mjs --mode=dry --limit=10
```

### 画面を出して送る（--headed）

画面を出さないChromiumは、reCAPTCHA v3（画面に出ない形式）の判定で弾かれることがあります。`--headed` を付けると、Macにインストール済みのChromeを画面ありで動かします。動いている間は、開いたChromeの窓を触らないでください。

```bash
node 一括送信.mjs --mode=send --headed --limit=80
```

### reCAPTCHAで失敗した会社を送り直す（--retry-recaptcha）

送付失敗のうち、メモが「送信時にエラー表示」で始まり、reCAPTCHAの確認に失敗したと出た会社だけを、1回だけ送り直します。この表示は相手のサーバーが受け付けを断ったもので、送信は届いていません。送り直した会社はメモの頭に「（再試行・画面あり）」のような印が付き、次からは対象になりません。

```bash
node 一括送信.mjs --mode=send --headed --retry-recaptcha
```

## Codexのクラウドで動かす

### 1. GitHubに置く（2026-10-20 済み）

非公開のリポジトリ `hitomik-droid/line-stock-cloud-sender`（https://github.com/hitomik-droid/line-stock-cloud-sender ）に置いた。このフォルダがリポジトリの直下になるので、下のセットアップの `cd クラウド送信` の行は要らない。以下は、別の置き場所を選ぶ場合の説明。

CodexのクラウドはGitHubのリポジトリを読み込んで動きます。このフォルダを次のどちらかに置きます。

1. 既存の `hitomik-droid/claude-line-ops` の中に、`クラウド送信/` フォルダとして入れる
2. 新しい非公開リポジトリを作る

### 2. 環境を作る（本人がChatGPTの画面で設定）

ChatGPTのCodexの設定（Environments）で、上のリポジトリに環境を作ります。

- セットアップスクリプト（環境を作る時に1回だけ動く）

```bash
cd クラウド送信   # リポジトリの直下に置いた時は、この行は要らない
npm ci || npm install
npx playwright install --with-deps chromium
```

- エージェントのインターネット接続：オンにする
  - 許可するドメイン：「すべて」にする。送り先のフォームは会社ごとに違うドメインのため、一覧で絞れない
  - 許可するHTTPメソッド：「すべて」にする。フォームの送信とステータスの更新にPOSTを使うため

インターネット接続をオフのままにすると、フォームもダッシュボードも開けません。

### 3. 1日100件を流す

Codexのクラウドで新しいタスクを作り、次の文を貼ります。

```text
AGENTS.md を読んでから始めて。
確認中の会社に、今日の分を送って。
node 一括送信.mjs --mode=send --limit=100
終わったら、まとめの欄（件数・手で送る会社・送れたか不明の会社）をそのまま貼って。
```

1つのタスクの時間には上限があるかもしれません。100社を4つのタスクに分けて同時に流す時は、組を分けて重ならないようにします。

```bash
node 一括送信.mjs --mode=send --part=1/4 --limit=25
node 一括送信.mjs --mode=send --part=2/4 --limit=25
node 一括送信.mjs --mode=send --part=3/4 --limit=25
node 一括送信.mjs --mode=send --part=4/4 --limit=25
```

`--part=k/n` は、確認中の会社をID順に並べ、n組に分けたk組目だけを送ります。4つのタスクにはそれぞれ別の組を指定します。

初回は `--mode=send --limit=1` で1社だけ送り、ダッシュボードのステータスと完了画面の文言を確かめてから、残りを流します。

### 4. 終わったら

- ダッシュボードで、送付完了・送付失敗・除外の件数を見る
- 送付失敗のメモに「手で送る」とある会社は、メモにあるフォームURLから手で送る
- 「送れたか不明」の会社は再送しない。相手から返信が来るか、自動返信メールが届いているかで確かめる
